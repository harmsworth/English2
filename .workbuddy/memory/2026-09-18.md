### ② 提交判分后错题本不刷新（用户报障，真正的 bug）

**现象**：整卷练习提交完，点「错题本」还是旧列表，必须手动刷新页面才重新取数。

**根因**：`useGradePracticeSection()` 的 `onSuccess` 只失效了 practice 域
（session / answers / incomplete / stats / typeAccuracy），**漏了 `mistakeKeys.all`**。
而判分 RPC 内部会把「客观题 + 答错」的题 upsert 进 `mistakes` —— 那是**另一个域**的缓存。
再加上全局 `staleTime` 是 5 分钟（`src/main.tsx`），切过去时错题本缓存仍算「新鲜」，
React Query 不会重新取数，于是看到的就是提交前那份列表。

**修法**（`src/hooks/use-practice-mutations.ts`）：把 `mistakeKeys` 加进 import，
并在 `onSuccess` 末尾补 `queryClient.invalidateQueries({ queryKey: mistakeKeys.all })`，
附一段注释说明「跨域 + 5 分钟 staleTime」这两个前提缺一不可。

### ④ 抽 `sumBy`，把「求和」和精度口径收敛到一处

项目里 5 处手写 `reduce((total, x) => total + x, 0)`：试卷小题数（ExamDetailPage）、
记录页的累计用时 / 判分题数 / 答对数（RecordsPage）、题型练习预览题量（DrillLauncher）。

新建 `src/lib/number.ts`：

```text
sum(values)                      整数求和
sumBy(items, pick)               按字段求和（少一次中间数组）
sumPrecise(values, decimals=2)   定点求和：放大成整数 → 求和 → 缩回
roundTo(value, decimals=2)       定点四舍五入（返回 number，不是 toFixed 的字符串）
```

**关于精度**（用户特意问的点）：JS number 是 IEEE-754 双精度，
只要参与运算的每个数及其部分和都是**安全整数**（|n| ≤ 2^53−1），加减就是**精确**的 ——
本项目所有求和（题数、秒数、计数）都落在这个范围，**不存在精度问题**。
真正会出问题的是小数（题分、金额）：`0.1 + 0.2 !== 0.3`，逐个相加会累积误差。
所以 `sumPrecise()` 用「放大成整数」的经典做法消掉二进制尾差，
并在注释里写明前置假设（每个元素小数位不超过 `decimals`）与
「需要任意精度就该上 `decimal.js`/`big.js`，或把金额存成整数最小单位（分），
而不是继续加补偿项」。**结论：当前不引入任何依赖。**

5 处调用点全部改为 `sumBy(...)`。

### 新踩的坑

1. ⚠️ **沙箱接管删除**：`Remove-Item` 走 safe-delete（进回收站），
   回收站通道失败时报 `SAFE_DELETE_FAIL_CLOSED` 且**拒绝硬删**；
   失败还会**中断整条 PowerShell 管道**，导致后面的 `Out-File` 不执行、日志文件压根不生成
   （看起来像「命令没找到」，其实是删除失败）。删不掉时改用 `Move-Item` 挪去 `$env:TEMP`。
2. ⚠️ **`cmd /c` 被 PowerShell 工具直接拦截**（`cmd.exe cannot be used from the PowerShell tool`），
   想探测某个命令在不在，用 `Get-Command` 而不是 `cmd /c xxx --version`。
3. ⚠️ **Playwright 里异步渲染的元素必须先 `waitFor` 再 `count()`**：
   第一次跑 probe8 时直接数年份按钮，页面还没把试卷拉回来，`years=0`，
   误判成「功能坏了」，其实是断言写早了。
