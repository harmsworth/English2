### ② 提交判分后错题本不刷新（用户报障，真正的 bug）

### ④ 抽 `sumBy`，把「求和」和精度口径收敛到一处

项目里 5 处手写 `reduce((total, x) => total + x, 0)`：试卷小题数（ExamDetailPage）、
记录页的累计用时 / 判分题数 / 答对数（RecordsPage）、题型练习预览题量（DrillLauncher）。

新建 `src/lib/number.ts`：

```text
sum(values)                      整数求和
sumBy(items, pick)               按字段求和（少一次中间数组）
sumPrecise(values, decimals=2)   定点求和：放大成整数 → 求和 → 缩回
roundTo(value, decimals=2)       定点四舍五入（返回 number，不是 toFixed 的字符串）
```

**关于精度**（用户特意问的点）：JS number 是 IEEE-754 双精度，
只要参与运算的每个数及其部分和都是**安全整数**（|n| ≤ 2^53−1），加减就是**精确**的 ——
本项目所有求和（题数、秒数、计数）都落在这个范围，**不存在精度问题**。
真正会出问题的是小数（题分、金额）：`0.1 + 0.2 !== 0.3`，逐个相加会累积误差。
所以 `sumPrecise()` 用「放大成整数」的经典做法消掉二进制尾差，
并在注释里写明前置假设（每个元素小数位不超过 `decimals`）与
「需要任意精度就该上 `decimal.js`/`big.js`，或把金额存成整数最小单位（分），
而不是继续加补偿项」。**结论：当前不引入任何依赖。**

5 处调用点全部改为 `sumBy(...)`。

### ③ 滑动切题「新卡先在底部出现，再跑到上面」（真 bug，两个独立成因）

**成因 A —— `mode="popLayout"` 静默失效。**
`PopChild` 靠 `React.cloneElement(children, { ref })` 拿 DOM 节点，
`ref.current === null` 时那段 `useInsertionEffect` **直接 return**，不做任何 `position:absolute` 注入。
而 `SwipeQuestionCard` 是普通函数组件，**没接收也没转发 ref** → 旧卡继续占文档流；
`AnimatePresence` 又是把退场子元素 `splice(0, 0, child)` 插在**最前面**渲染的，
新卡就被排到旧卡**下面**，旧卡卸载瞬间再整体跳上去 —— 正是用户描述的现象。
修法：`SwipeQuestionCard` 增加 `ref?: React.Ref<HTMLDivElement>` 并转发到最外层 `m.div`。
（React 19 里函数组件可以直接把 `ref` 当普通 prop 收，不用 `forwardRef`。）

**成因 B —— 入场动画压根没播。**
`initial="enter"` 是 variant **函数**，靠 `custom` 拿方向。但 framer-motion 算初始状态走
`makeLatestValues()` → `resolveVariantFromProps(props, name)` **不传 custom**，
于是回退 `props.custom`（我们没传）= `undefined` → 解析出 `{x: 0}` → 新卡从 0 滑到 0。
`exit` 没这问题（退场走动画通路，custom 由 AnimatePresence context 给）。
修法：`initial` 改成**直接给对象** `makeEnterOffset(enterFrom, mobile)`，
并把 `enterFrom` 作为 prop 从 `PracticeRunner` 传下来。

**顺带拆成两层**（各层需要不同所有权）：
外层 `m.div` 只管出入场滑行（x 由 motion 持有 —— 外部 MotionValue 会让 `initial` 不被写入）；
内层 `m.div` 只管拖拽跟手（`x` 是我们自己的 MotionValue，「没达标/撞边界」要 `animate(x, 0)` 回位）。
额外好处：旧卡退场时内层仍停在手指放开的位移上，外层再从 0 滑到 -100%，
合成结果就是**从手指离开的地方继续滑出去**，不回弹。

   补 PATH 也**没用**（git 似乎不走继承的 PATH）。
   **绕过**：`git push "https://$(gh auth token)@github.com/OWNER/REPO.git" main` —— token 不落任何配置。
   普通终端里不需要这么干，助手本身是好的。
2. ⚠️ 用显式 URL 推完，**本地的 `refs/remotes/origin/main` 不会更新** ⇒ `git status -sb` 仍显示 ahead N。
   而且这时 `git fetch` 也会因为同样的凭据问题失败 ⇒ 手动同步：
   `git update-ref refs/remotes/origin/main HEAD`（远端 HEAD 先用 `gh api repos/OWNER/REPO/commits/main` 核对）。
3. ⚠️ PowerShell 里 `git log --format='%H %s'` 会被安全策略拦（`%VAR%` 被当成 cmd 语法）⇒ 别用 `%` 占位符；
   另外要看清中文提交信息，先设 `[Console]::OutputEncoding=[System.Text.Encoding]::UTF8`，
   否则 git 输出的 UTF-8 被按 GBK 解码、日志里全是乱码（**但 commit 本身是对的**）。
4. 盘点时仓库是 **PUBLIC**，推送后再查变成 **PRIVATE**（用户中途改的，我没动可见性）。
   公开前值得再确认一次 Supabase Auth 是否允许陌生人注册 —— 公开站点 = 任何人可注册刷你的库。
