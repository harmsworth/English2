## `cn` npm 依赖去留调查（结论：保留，不移除）

- 代码引用：全项目 `from "cn"` / `require("cn")` = **0** 处（唯一命中是 README 第 183 行说明文字）。UI 组件 button.tsx / card.tsx 均用 `@/lib/utils` 的自实现 `cn()`（clsx + twMerge）。components.json 无 cn 配置。
- **@shadcn/lint 不强制依赖 npm `cn`**（源码实证 `node_modules/@shadcn/lint/dist/index.js`）：`resolveCnConfig()` 先 `require.resolve("cn/config")`，版本 < 0.2.6 才 warn 并回退；**解析失败（catch）直接用 `bundled()`**（内置 cn 0.2.6 grammar）。且 `@shadcn/lint` 自身硬依赖 `cn: "0.2.6"`（精确锁），内置 grammar 永远可用。
- **但 `cn` 是别人的传递依赖**：`shadcn@4.21.0` → `cn@^0.2.4`；`@shadcn/lint@0.1.0` → `cn@0.2.6`。所以 `pnpm remove cn` 只会删掉根 `node_modules/cn` 符号链接 + package.json 一行，`.pnpm/cn@0.2.6` 仍在，cn 不会真正离开项目。
- **shadcn CLI 会自动写回 cn**：其 dist 中新组件固定生成 `moduleSpecifier: "cn"`（`import { cn } from "cn"`）+ "Installing dependencies" 步骤补装。实测：Phase 1 里 `pnpm remove cn` 之后跑一次 `shadcn add card`，cn 就被写回 package.json。以后每加组件都会重现。
- 另一代价：移除后 @shadcn/lint 的 class 分组从"项目 cn 0.3.0"回退到"内置 cn 0.2.6"（当前 0 条 shadcn 规则，暂无影响）。注意本项目运行时实际是 `twMerge(clsx(...))`（tailwind-merge 3.7.0），并非 cn 包，所以两条路都不是 100% 匹配。
- 决策：按用户设定的删除门槛，条件 E「其他依赖没有依赖 npm cn」不成立 → 先建议保留；**用户随后明确要求删除，已执行 `pnpm remove cn`**。
- 删除后实测（2026-09-15 10:31）：`pnpm lint` exit 0（仍是原来那 1 条 button.tsx fast-refresh warning）、`pnpm build` exit 0，产物 hash 与删除前完全一致。
- 删除后状态：根 `node_modules/cn` 消失；`require.resolve('cn/config')` 解析失败 → @shadcn/lint 走 `catch → bundled()`（内置 cn 0.2.6 grammar）；`@shadcn/lint` 自身嵌套的 `cn@0.2.6` 仍在，插件 `require('@shadcn/lint')` 正常加载（exports: plugin/project/default）。`pnpm why cn` 显示仅剩 shadcn 与 @shadcn/lint 两条传递依赖。
- **后续维护注意**：每次执行 `pnpm dlx shadcn@latest add <组件>` 后，`cn` 会被 CLI 自动写回 package.json（CLI 生成 `import { cn } from "cn"` + 自动补装），需再删一次并把新组件的 import 改成 `@/lib/utils`。
