## 解除 SQL 备份 BLOCKED + Phase 6 判分通路方案分析

- 用户决定：**不再把 SQL 备份作为线上数据库变更的前置条件**。`progress.md` 的 Blocked 段已改写为「已解除」，`phase-06` 的第 3 条前置同步改为「变更写成新 migration 保持可追溯」。
- 就判分通路给出对比与推荐（**尚未拍板，未写 decisions.md、未写 migration**）：
  - **推荐 A：服务端判分 RPC（SECURITY DEFINER）**，且做成「提交整个大题时批量判分一次」而非每题判分。
  - **B（放宽列级权限）否决**：HTTP 无状态，数据库不知道"是否已提交"，GRANT 回来后任意 authenticated 可随时拖走全部 816 题答案；且列级权限无法用 RLS 表达（RLS 只管行不管列）。等于回退 Phase 2/5C。
  - **C（Edge Function）**：效果同 A，但要多部署一套 Deno 运行时，对家庭项目过度。
- A 的三个实现要点（将来真做时必看）：
  1. **必须在函数内校验 `ps.user_id = auth.uid()`** —— 否则任何人传任意 session_id 就能提权拿答案，这是 SECURITY DEFINER 最经典的漏洞。
  2. 必须 `set search_path = public, pg_temp`。
  3. 判分结果 `is_correct` 应在服务端写回 `practice_answers`，不要前端回写（否则错题本数据可被用户篡改）。
- 概念澄清（避免以后走偏）：安全目标**不是**"用户永远看不到答案"——提交后看到正确答案与解析正是学习闭环的核心；目标是**不能在未作答时批量获取全库答案**。
- 翻译题参考答案在 `section_items.extra_data.reference_translation`，需走同一 RPC 通路返回（该列已被 REVOKE）。
