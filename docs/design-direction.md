# Design Direction（草案）

**状态：** 草案 · 仅分析输出，**未修改任何代码**
**输入源：** `svgs/*.svg`（网页端 1440×960）+ `svgs/mobile/*.svg`（移动端 375，上一轮据此重排）
**关联文档：** [`design-system.md`](./design-system.md)（Token 与组件规格）、[`README.md`](./README.md)（索引）
**适用对象：** English2 考研英语二真题学习系统（2010–2026，17 套）

---

## 1. 一句话方向

> **把 English2 从「一套用默认组件搭出来的可用界面」，变成「一间安静的真题档案馆」——
> 以衬线字体、暖白纸面与墨绿主色建立学术信任感，用克制的排版层级而非装饰性 UI 传达"这是真考题，值得认真对待"。**

设计稿已经把答案给了出来：它不追求 App 化的圆润与活泼，而是刻意往**出版物 / 档案索引**的方向靠 ——
大号衬线标题、极细的分隔线、表格化的试卷索引、状态用小胶囊而不是色块。这套语言与产品内容（历年真题、成人自学者、长时间阅读）高度契合，应当保留并强化，而不是在落地时被"现代化"掉。

## 2. 现状 Gap：设计稿与现有实现的差距

先把差距摊开，因为它决定了后续工作是**换皮**还是**重构**。

| 维度 | 设计稿 | 现有实现（`src/`） | 差距性质 |
| --- | --- | --- | --- |
| 主色 | 深墨绿 `#1F4A45` | shadcn 默认 indigo `oklch(0.53 0.16 265)` | **Token 替换**，一行 |
| 底色 | 暖白 `#FAF9F6` | 纯白 `oklch(1 0 0)` | **Token 替换** |
| 标题字体 | 衬线（Georgia / Source Serif 系） | `--font-heading: var(--font-sans)`（Geist，无衬线） | **Token 替换**，视觉冲击最大的一处 |
| 描边 | 暖灰实线 `#EBE8E2` | `ring-1 ring-foreground/10`（冷灰半透明） | **Token 替换** |
| 页面容器 | 内容宽 1280，左右留白 80；详情页 2:1 分栏 | 全部页面 `max-w-3xl`（768px）单栏 | **结构性**：列表/详情需加宽 + 分栏 |
| 全局框架 | 顶部导航（logo + 徽标 + 头像）；移动端底部标签栏 | **无 App Shell**，每页只有「← 返回首页」链接 | **结构性**：需新建 AppShell |
| 组件 | 卡片 / 徽章 / 进度条 / 表格 / 题号格子 / 计时胶囊 | 仅 `button` `card` `input` 三个 ui 组件；**无 Badge / Progress / Table / Tabs** | **补组件** |
| 触控尺寸 | 按钮 44–46px 高 | Button `size` 最大 `h-9`（36px），默认 `h-8`（32px） | **补尺寸变体** |
| 表格 | 桌面表头 + 行分隔的试卷索引表 | 列表页为卡片流（无表格） | **新增**（桌面）/ 保留卡片（移动） |
| 深色模式 | 设计稿只给了浅色 | `index.css` 有完整 `.dark` 变量 | **待决策**：补深色 token 或暂不支持 |

**结论：约 60% 是 Token 层的替换（低成本、高收益），40% 是结构性工作（App Shell、分栏、补组件）。**
建议按「先换皮、再补件、后重构」三段推进，见 §12。

## 3. 设计原则

### P1 · 内容即界面（Typography-first）
- **是什么**：层级靠字号 / 字重 / 字族 / 留白建立，不靠色块与边框堆叠。
- **为什么**：核心内容是长篇英文篇章与题目，任何装饰都会和正文抢注意力。
- **怎么做**：分隔线优先于卡片；卡片优先于阴影；**禁用** 渐变、玻璃拟态、彩色大面积背景。
- **反例**：给每个 Section 套不同底色、给标题加渐变文字、用阴影做层级。

### P2 · 档案感（Archive, not App）
- **是什么**：像在查阅一套装订好的真题卷宗 —— 编号、表格、状态、进度，都是"检索"语汇。
- **为什么**：用户的核心动作是"找到某年某题、知道做到哪、错了什么"，本质是检索而非浏览。
- **怎么做**：年份做大号衬线数字、题组用圆形序号、状态用小胶囊、进度用细条百分比。
- **反例**：卡片流做成信息流瀑布、用 emoji 表示状态、把试卷做成带封面的图卡。

### P3 · 安静的信任感（Quiet confidence）
- **是什么**：低饱和、低对比噪声、一个强调色（墨绿）+ 三个语义色（绿/琥珀/红），其余全是中性色。
- **为什么**：长时间阅读场景下，高饱和与多色会加速疲劳；墨绿同时传达"学术""沉稳""可信赖"。
- **怎么做**：强调色只用于**可点击**与**当前状态**；语义色只用于**结果反馈**；正文永远中性。
- **反例**：紫色/蓝色渐变按钮、彩色标签墙、悬浮彩色光晕。

### P4 · 状态必须看得懂（Legible state）
- **是什么**：每个列表项都要能一秒回答"做到哪、什么状态"。
- **为什么**：17 套真题 × 多年练习，用户回来时第一件事是"我上次做到哪了"。
- **怎么做**：状态徽章（未开始 / 进行中 / 已完成）+ 进度条 + 百分比，**三位一体**，缺一不可。
- **反例**：只用颜色点表示状态、只显示"已完成"而不显示进度。

### P5 · 移动优先的真实触达（Touch-honest）
- **是什么**：移动端不是桌面缩小版，而是**重排**：表格→卡片、右栏→抽屉、顶部导航→底部标签栏。
- **为什么**：真题练习的主要场景是碎片时间（手机），单栏 + 大触达区 + 底部可达的操作条才成立。
- **怎么做**：主操作 44px 起、并排按钮改全宽纵排、长内容留在单栏、高频操作下沉到底部。
- **反例**：把桌面表格横向滚动塞进 375、把主按钮放在右上角、把筛选折叠进多层菜单。

## 4. 视觉语言

### 4.1 气质关键词

```
学术 · 沉静 · 可检索        不是   活泼 · 圆润 · 游戏化
纸面 · 有温度的白           不是   冷白 / 纯数字灰
克制 · 一色强调             不是   多彩 / 渐变
```

### 4.2 图形语言
| 元素 | 规则 |
| --- | --- |
| 分隔 | **1px 实线 `#EBE8E2`** 是主要的分组手段；卡片内分隔用更浅的 `#F0EEE9` |
| 边框 | 比阴影更常用；卡片 = 白底 + 1px 暖灰边 |
| 阴影 | 极轻（仅抽屉 / 悬浮层），常规卡片**不加阴影** |
| 圆形 | 圆形序号徽记（题组 1-4、题号格子），`radius` 8–12px 的方为主 |
| 胶囊 | 徽章 / 计时器 / 小标签用 `radius` 999 或 4–6px 小圆角，高度 18–26px |
| 图标 | 线性、1.5–1.6 描边、无填充；仅用于导航与操作，不作装饰 |

### 4.3 圆角 / 描边 / 阴影
- 卡片 `12px`、按钮 `8px`、输入框 `8px`、徽章/胶囊 `4–6px`、题号格子 `7px`、抽屉顶部 `16px`。
- 描边统一 `1px`；选中态用 **`1.5px` 主色**（比加粗更克制，且能避免布局跳动 —— 推荐用 `ring` 或 `outline` 实现，不改 border 宽度）。
- 阴影仅两级：`sm`（卡片悬浮/抽屉）、`md`（底部抽屉与弹层）。

## 5. 版式与布局哲学

### 5.1 桌面（≥1024）
- 画布 1440，**内容宽 1280，左右留白 80**。
- 列表页 / 详情页 / 结果页采用 **2:1 分栏**（主栏 ≈840，侧栏 ≈400，间距 40）。
- 侧栏承载"元信息 + 次要动作"：Instructions、Question Map、Your Performance、错题回顾。
- **例外（重要）**：**阅读型内容（篇章、题干、解析）不应占满 1280**。长英文行超过 ~75 字符会显著降低可读性，
  建议阅读区（Practice 题干 / Passage）保持 **720–768px**，与现有 `max-w-3xl` 一致。
  ⇒ **加宽的是检索型页面（列表/详情/结果），不是阅读型页面。**

### 5.2 移动（<768）
- 单栏，左右边距 **20px**（与现有 `px-5` 一致，无需改），卡片整宽 335px。
- 侧栏内容三种归宿：①**下移为整宽卡片**（Instructions、Your Performance、错题回顾）②**收进底部抽屉**（Question Map）③**前移为顶部标签**（章节进度、题号计数）。
- 顶部导航 → **底部标签栏**（56px + 安全区），主操作进入 **sticky 底部操作条**。
- 按钮并排 → **全宽纵排**，最小高度 44px。

### 5.3 断点策略
只设三档，不做中间态的花哨适配：`mobile (<768) / tablet (768–1023) / desktop (≥1024)`。
平板沿用桌面分栏但收窄留白到 40px；侧栏在 <1024 时并入主栏（同移动端规则）。

## 6. 字体方向

- **展示字体（Display / Heading）**：衬线。用于 Logo、Hero 大标题、页面标题、大题标题、题干、大数字（分数 / 年份）。
  建议 `Source Serif 4`（可变字体，`@fontsource-variable/source-serif-4`），回退 `Georgia, 'Times New Roman', serif`。
- **正文字体（Body）**：无衬线。保留现有 **Geist Variable**（已通过 `@fontsource-variable/geist` 引入，零新增成本），中文回退 `PingFang SC / Microsoft YaHei`。
- **数字**：计数、百分比、题号、分数一律 `tabular-nums`，避免跳动；大数字用衬线，小数字用无衬线。
- **中英混排**：标题中的中文**不要**回退到宋体（Windows 上 SimSun 观感很差）——
  建议 `--font-heading` 的 CJK 回退仍用无衬线（`PingFang SC` / `Microsoft YaHei`），
  即**拉丁衬线 + 中文黑体**混排，这在中文产品里是成熟做法。
- **不要用**：手写体、圆体、超细字重（<400）作正文；不要把正文设为衬线（长英文阅读下无衬线更稳）。

## 7. 色彩方向

- **底色**：暖白 `#FAF9F6`（不是纯白）—— 这是"纸感"的来源，也是与 shadcn 默认最明显的区分点。
- **主色**：深墨绿 `#1F4A45`。只用于**可点击元素**与**当前/选中态**，禁止当背景大面积铺。
- **语义色**：绿 `#2C7958`（正确/完成）、琥珀 `#926511`（进行中）、红 `#B04A3E`（错误/危险）。
  三者都有对应的 `-soft` 浅底（`#E3F1EA` / `#FBF0D9` / `#F9E9E6`）用于徽章底与卡片底。
- **中性**：墨黑 `#1A2626`、次要文字 `#6A7571`、弱化文字 `#8A948F`（**仅装饰，不承载小字**）、描边 `#EBE8E2`、控件描边 `#D8D4CC`、轨道 `#E8E6E0`。
- **明确不用**：紫/蓝渐变、荧光色、超过 3 个强调色、纯黑 `#000`、纯白背景配冷灰描边。

> ⚠️ 采样时实测：设计稿中的 `--muted` `#6F7B77` 在暖白底上对比度 **4.18**，未达 AA 正文 4.5；
> 徽章中的 success / warning 文字在各自 soft 底上为 4.29 / 4.14，同样未达标。
> **本方案给出已达标替代值**（`#6A7571` / `#2C7958` / `#926511`），详见 [`design-system.md` §3.3](./design-system.md#33-可访问性修正已实测)。

## 8. 组件方向

- **少而稳**：组件数量控制在 15 个以内（见 design-system §8），每个组件有明确的状态集合。
- **状态优先**：任何可交互组件必须定义 `hover / active / focus-visible / disabled / 选中` 五种状态，且**不只靠颜色**区分（配边框、字重或图标）。
- **尺寸收敛**：控件高度只有 4 档（`28 / 32 / 40 / 44`），卡片内间距只有 3 档（`12 / 16 / 20`）。
- **不做**：不引入第三方 UI 库；不做自定义下拉/日期等重型控件；不为单个页面造一次性组件（先在页面内实现，出现第 3 次再抽）。

---

## 9. 动效与反馈

- 时长：`120ms`（hover/颜色）→ `180ms`（展开/位移）；**不做**超过 300ms 的过渡。
- 缓动：`ease-out` 为主；禁止回弹/弹性曲线（与"安静"冲突）。
- 允许：颜色过渡、轻微位移（`translate-y-px` 的按下反馈）、抽屉上滑、进度条填充。
- 禁止：页面级大动画、列表入场逐个飞入、图标旋转循环、骨架屏闪烁（用静态骨架 + 文案）。
- **必须**尊重 `prefers-reduced-motion`（现有 `index.css` 已全局兜底，保留即可）。

## 10. 可访问性方向（底线，不可协商）

1. 正文对比度 **≥ 4.5:1**，大字号与 UI 控件 **≥ 3:1**；所有 token 已实测（见 design-system §3.3）。
2. 触控目标 **≥ 44×44**（不足时用透明 padding 扩大命中区）。
3. 焦点环可见：统一 `ring-3 ring-ring/50`，**不移除** outline。
4. 状态不能只靠颜色（徽章同时有文字；选中态同时有边框与底色）。
5. 语义优先：徽章用 `<span>` + 可读文本，列表用 `<ul>/<li>`，标签栏用 `role="tablist"` 或 `<nav>`。
6. 支持系统字号缩放（用 `rem`，不用固定 `px` 字号）。

## 11. 与产品阶段的契合 & 风险

**契合**：产品处于"内容已全（17 套）、功能在补（错题/历史）"的阶段。
此时统一视觉语言的收益最高 —— 后续新增的错题本、学习历史、重做流程都能直接套用现有组件，不必二次返工。

**风险与应对：**

| 风险 | 说明 | 应对 |
| --- | --- | --- |
| 加宽到 1280 会伤阅读体验 | 长英文行过宽 | 只加宽检索页，阅读区保持 720–768（§5.1 例外） |
| 衬线字体中文观感差 | Windows 回退到宋体 | CJK 回退用黑体，拉丁用衬线（§6） |
| 移动端稿里的功能尚未实现 | 计时器、题号地图、Submit | 标记为"设计稿领先实现"，实现到哪步用哪步，不要为了对齐设计稿临时造功能 |
| 深色模式无设计稿 | 现有 `.dark` 会与暖白体系冲突 | 本轮**不动深色**；后续单独出一版深色 token，不要自动反色 |
| 一次性全量重构 | 影响面过大 | 三段式推进（§12），每步可独立验收回滚 |

## 12. 落地路径建议（**未执行，供决策**）

| 阶段 | 内容 | 影响面 | 可独立验收 |
| --- | --- | --- | --- |
| **S1 · 换皮** | 只改 `src/index.css` 的 `@theme` 与 `:root`：主色/底色/描边/字体族/圆角 | 1 个文件 | ✅ 页面结构不变，视觉整体切换 |
| **S2 · 补件** | 新增 `badge` `progress` `input` 变体；Button 增 `touch` 尺寸；统一焦点环 | 4–5 个文件 | ✅ 各页面逐步替换手写徽章/进度条 |
| **S3 · 重构** | 新建 `AppShell`（顶栏/底部标签栏）；列表页加宽 + 表格化；详情页 2:1 分栏；练习页 sticky 操作条 | 路由 + 4 个页面 | ✅ 按页面逐个切换 |

**建议顺序**：S1 → 用现有页面验收观感 → S2 → S3（先列表页，再详情页，最后练习页）。
每步结束都应跑一次 `tsc -b` + `lint` + 375px 溢出检查。

## 13. 开放问题（需决策后才能进入 S3）

1. **容器宽度**：列表/详情/结果页是否真的加宽到 1280？还是维持 768 只做视觉统一？
2. **App Shell**：是否引入全局顶栏？（涉及登录态展示、退出入口的重新安置）
3. **底部标签栏的 4 个入口映射**：设计稿是 Home / Exams / Study / Settings，现有路由只有
   `/`、`/exams`、`/mistakes` —— **Study 指向错题本还是"继续上次练习"？Settings 是否本轮不做？**
4. **深色模式**：本轮冻结、后续补，还是直接移除 `.dark`？
5. **设计稿领先实现的功能**：计时器、题号地图、Submit Examination —— 是否排期？（当前代码无对应能力）
6. **中文字体**：是否需要为标题引入中文衬线（如思源宋体）？（自增约 1–2MB 字体资源）

## 附录 B：本文件的采样方法与精度

- 颜色、间距、字号均为**从 SVG 渲染图采样 + 移动端稿（手写，精确值）交叉验证**。
- 桌面稿为矢量路径，部分字号/字重为**视觉估算**，标注为「≈」；落地前应在浏览器中以设计稿为基准核对一次。
- 对比度数据为**脚本实测**（sRGB → OKLCH → WCAG 公式），非估算。
